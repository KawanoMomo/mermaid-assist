## 3. 案

### 案A — 折り畳み見出し(推奨)

追加フォームと一覧を折り畳み可能な見出しにする。**既定は「追加フォーム=開、一覧=閉」。**

```
┌─ PROPERTIES ──────────────┐
│ [一覧を絞り込む (399件)]   │
│ Flowchart   方向 [TD ▼]   │
│                           │
│ ▼ ノードを追加             │   ← 開いている
│   ID    [        ]        │
│   ラベル [        ]        │
│   [rect ▼]  [+ 追加]      │
│                           │
│ ▶ エッジを追加        (2)  │   ← 閉じている。( ) は既存件数
│ ▶ サブグラフを追加    (0)  │
│                           │
│ ▶ ノード一覧        (200)  │   ← 閉じている
│ ▶ エッジ一覧        (199)  │
└───────────────────────────┘
      画面内に収まる(はみ出し 0px)
```

- 開閉状態は図種ごとに覚える(次に同じ図種を開いたとき同じ形)
- 見出しをクリック / Enter で開閉。`A` キーは「開いている最初の追加フォーム」へ移動(現状維持)
- **UI-022 と UI-023 の両方が同時に解ける**

| | 前 | 後(見込み) |
|---|---|---|
| architecture のはみ出し | 520px | 0px |
| 200要素の一覧の高さ | 18685px | 43px(閉じている) |
| 目的のノードに触るまで | 約90ホイール刻み | 見出しを開く1回 + 絞り込み |

**代償**: 一覧を見るのに毎回1クリック増える。一覧を常時見ている使い方だと悪化する。

---

### 案B — タブ分割

パネルの上部にタブを置き、「追加」「編集」「一覧」を切り替える。

```
┌─ PROPERTIES ──────────────┐
│ [追加] [編集] [一覧 399]   │   ← タブ
│───────────────────────────│
│ ノードを追加               │
│ ID    [        ]          │
│ ラベル [        ]          │
│ [rect ▼]  [+ 追加]        │
│                           │
│ エッジを追加               │
│ …                        │
└───────────────────────────┘
```

- 3つの状態がはっきり分かれる
- **代償**: 「一覧から選んで編集する」流れでタブを2回切り替える。今は1画面で完結している

---

### 案C — 一覧だけ高さを固定してスクロール領域にする

構成は変えず、一覧部分に `max-height` を付けて内部スクロールにする。

```
│ ノード一覧                 │
│┌─────────────────────────┐│
││ ノード0 (N0, rect) 編集 ✕││  ← ここだけ内部スクロール(300px)
││ ノード1 (N1, rect) 編集 ✕││
││ …                      ││
│└─────────────────────────┘│
│ エッジ一覧                 │
```

- 変更が一番小さい。追加フォームの位置は変わらない
- **代償**: UI-023(追加フォームのはみ出し)は**解けない**。一覧の中で 18685px を走査するのも変わらない

---

### 案D — 何もしない

- 200要素を超える図はそもそも作らない、という運用で回す
- **代償**: 実測の摩擦(180ホイール刻み・520pxのはみ出し)がそのまま残る

## 4. 比較

| | 案A 折り畳み | 案B タブ | 案C 高さ固定 | 案D 現状 |
|---|---|---|---|---|
| UI-023 はみ出し(15図種) | **解ける** | 解ける | 解けない | 解けない |
| UI-022 走査距離 | **解ける** | 解ける | 部分的 | 解けない |
| 一覧を見る手数 | +1クリック | +1クリック | ±0 | ±0 |
| 一覧→編集の流れ | 変わらない | **+2切替** | 変わらない | 変わらない |
| 実装の大きさ | 中(21図種の renderProps 共通部) | 大 | 小 | なし |
| 既存 e2e への影響 | 中(一覧を直接見る検査が閉じた状態になる) | 大 | 小 | なし |

**推奨は案A。** UI-022 と UI-023 が同時に解け、既存の「一覧→編集」の流れを壊さないためです。
