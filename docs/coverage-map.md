# 測った場面と、測っていない場面

- **作成**: 2026-08-22(ラウンド65)
- **なぜ作ったか**: ラウンド64 の診断で「製品の欠陥は尽きた」と結論したが、
  **翌ラウンドに未測定の領域を1つ開けただけで Major が1件出た**(UI-064)。
  「尽きた」ではなく「**同じ場所を測り続けていた**」が正しかった。
  勘で判断しないよう、場面を一覧にする。

## 読み方

| 記号 | 意味 |
|---|---|
| **測定済** | 実測した。結果が review-log か backlog に残っている |
| **未測定** | 一度も測っていない。**素材があれば今すぐ測れる** |
| **測定不能** | 実機・実運用の素材が要る。**素材のご提供が前提** |

## 測って「指摘なし」だったもの(R65)

**1つの図が極端に大きい**: 1000要素は13.3秒で描画され、2000要素で mermaid の
配置計算が破綻する。破綻したときの扱いは正しかった:

- 帯に「要素が多すぎて mermaid の配置計算が破綻しました(こちらの設定では回避
  できません)。図を分割してください。」— **限界の所在(mermaid 側)と、次の行動
  (分割)の両方を言う**
- `previewStale=true` で**直前の図が残る**。真っ白にならない
- `mermaid.parse` は通ることを確認済み。構文エラーと描画限界を取り違えていない

**指摘にしない理由**: 実務は数十〜数百要素(ペルソナ定義)で、1000要素は範囲外。
遅さは事実だが、範囲外の遅さを Nit にすると優先度の目盛りが狂う。

## 判断が要るもの (私の一存では進めない)

**一括改名 / 置換の経路が無い** (R65 実測)

- 一括**削除**は `Shift + クリック` → `Delete` でできる (ヘルプにも記載済み)
- 一括**改名**の経路は無い。エディタは素の `<textarea>` で `Ctrl+H` は無反応
- 5要素の `ComM_Init` / `EcuM_Init` … を `_Initialize` に直すには、
  編集ボタン5回 + 入力5回 + 確定5回 = **15操作**

**これは欠陥ではなく機能追加**なので、実装は判断を仰ぐ。
「レビュー指摘で用語を統一する」は日常的に起きる作業だが、
どこまでを本ツールが引き受け、どこからをエディタ (VS Code 等) に任せるかは
製品の線引きの問題であり、測定では決められない。
