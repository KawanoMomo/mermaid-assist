# ECN-035: 文書を入れ替えても前の図の状態が残る欠陥を塞いだ (A113〜A116)

- **ステータス**: 適用済 (未マージ)
- **種別**: 不具合修正
- **バージョン**: (未リリース / PR #17)
- **対象コミット**: `5f167db`, `b74c2f0` (PR #17)
- **影響ファイル**: src/app.js, src/modules/{block,c4,gantt}.js
- **マイルストーン**: モジュール直下の可変状態を全21図種で棚卸しし、掃除の対象に入れた

## コンテキスト

利用者から「ガントチャートの操作感が悪くなっていた → **バーのドラッグ**」という報告があった。

調べた結果、**原因は修正済みなのに届いていないこと**だった。作業ツリーが
`origin/master` より 74 コミット遅れており、PR #16 も未マージだった。
マージと `git pull` で 112 コミットを配送し、実機で解消を確認した。

| 書き方 | 配送前 | 配送後 |
|---|---|---|
| `after` 依存 | **動かない** | 動く |
| 状態付き `:done,` | **動かない** | 動く |
| 週単位 `2w` | **動かない** | 動く |
| マイルストーン混在 | 動かない | **本 ECN の A116 で修正** |

この調査の過程で、同じ「静かに間違った場所へ書き込む」型の欠陥が 3 件見つかった。

## 何を変えたか

### A113 / A114 — 文書を入れ替えても前の図の選択が残る

`block` は「最後に足した親グループ」を、`c4` は「最後の種類と親境界」を覚えている。
同じ文書の中では便利だが、**別の文書を開いても残っていた**。
実務では図をまたいで命名が揃う (どの図にも `G1` がある) ので、
開いた直後に追加を押すと**選んだ覚えのないグループの中に入る**。

根は 2 つに見えて 1 つだった。

| 段階 | 見つかったこと |
|---|---|
| 1 | 掃除の仕組み (`resetTransientState`) はあったが、実装しているのは `gantt` だけ |
| 2 | 足しても図種の切替経路が残る — 切替は**切替*先***を掃除するので切替*元*が汚れたまま |

どのモジュールが汚れているかを追うのをやめ、
**文書が入れ替わったら全モジュールを掃除する** (`resetAllTransientState`) 形にした。

全 21 モジュールを走査し、モジュール直下の可変状態は `block` と `c4` の 2 つだけと確認した
(他は関数ローカルなので文書をまたがない)。

`c4` の方が重い — **種類**まで覚えるので、外部システム (`System_Ext`) が
意図しない境界に入る。C4 では `System` と `System_Ext` は別の意味を持つ図形なので、
位置のずれだけでなく**図の読み違い**に直結する。

### A115 — 契約経路が引数を 1 つ落としていた

`c4` の `operations.add` が `addElement` を **6 引数**で呼んでいた (宣言は 7 引数)。
`parentId` が常に undefined で、UI パネルからは正しく境界に入るのに、
**契約どおり呼ぶと黙ってトップレベルに出る**。

「UI 経路だけ実装して契約経路を忘れる」型の **17 例目**。

あわせて入れ子の字下げが**固定幅**で、文書の流儀を見ていなかった。

| 図種 | 既存の子の字下げ | 直す前 | 直した後 |
|---|---|---|---|
| c4 | 8 | 4 (**−4**) | 8 |
| block | 8 | 2 (**−6**) | 8 |

### A116 — マイルストーンを起点にしたガントで掴んでも動かない

```
節目 :milestone, m1, 2026-03-01, 0d
実装 :t2, after m1, 10d
```

`m1` は開始日を持つが期間が `0d` (割ると壊れる)。`t2` は期間を持つが開始日が無い。
どちらも単独較正の条件を満たさず、2 点較正にも足りないため `pxPerDay` が 0 のままだった。
**バーもリサイズハンドルも描かれるのに、掴んでも 1 ミリも動かない。**

**倍率と原点を別々の相手から取れる**ようにした。
マイルストーンは菱形で描かれ矩形として照合できない (`barRects[0]` が null) ので、
原点には `after` を解決した開始日 (`resolveSpan` が返す `starts`) を使う。

**実測: pxPerDay 0 → 54.4。**

## 影響範囲

- 文書を開く経路と図種の切替経路の両方で、全モジュールの一時状態が捨てられる
- `c4` の契約経由の追加が、指定した境界に入る
- マイルストーンを含むガントで較正が成立する

## 検証

- ユニット +8 本 (契約経由の入れ子追加)、e2e +5 本
- 変異注入で確認: `resetTransientState` を外す / 契約経路の引数を落とす /
  字下げの追従を無効化 / マイルストーン較正を無効化 — いずれも対応するテストが落ちる

## 姉妹プロジェクトへの示唆

- **モジュール直下に「最後に使った○○」を持つ実装は、文書の入れ替えで捨てているか**
  05 では 21 モジュール中 2 つが該当し、どちらも掃除されていなかった
- **UI 経路と契約経路で引数の数が合っているか** — 呼び出し側の引数が宣言より
  少ない箇所を機械で数えると見つかる (05 では 8 件検出し、1 件が実害)
