# ECN-036: 黙って起きていたことを言うようにした (B29〜B35)

- **ステータス**: 適用済 (未マージ)
- **種別**: 改善
- **バージョン**: (未リリース / PR #17)
- **対象コミット**: `b74c2f0` (PR #17)
- **影響ファイル**: src/app.js, mermaid-assist.html, src/ui/properties.js, src/modules/{gantt,er,state,class}.js
- **マイルストーン**: 「起きたことを言う」機能を 7 件追加。うち **2 件が実装中に自分の欠陥をあぶり出した**

## コンテキスト

前 ECN で直した欠陥は、いずれも「**黙って**間違った場所に書き込む」形だった。
同じ根で「**黙って**何も起きない」「**黙って**違うものが出る」箇所が残っていたので、
まとめて言うようにした。

外部でも同型の不満が挙がっている
(「`after` が存在しない ID を指しても Mermaid は警告せず任意の位置に置く」
「括弧の位置がずれると、問題を指し示さない不可解な失敗になる」、2026-08-22 確認)。

## 何を変えたか

| # | 内容 | 直す前の実測 |
|---|---|---|
| **B29** | `after` の指す先が無いとき、**どのタスクのどの id か**を出す | `status-parse` は "OK"、`status-info` は「タスク: 2 \| セクション: 1」のまま |
| **B30** | 版をステータス行に出す | 画面に `\d+\.\d+\.\d+` が **1 つも無く**、`VERSION` はファイルにあるだけで参照されていなかった |
| **B31** | 書き出した線を白地で見える濃さにする | flowchart のコントラスト比 **1.61** (204,204,204) |
| **B32** | class の並べ替えを UI に戻す | 古い経路は**空振り**、契約経路はブロックごと正しく動く |
| **B33** | 書き出しで色を変えたことを本数つきで告げる | 何も言わない |
| **B34** | 並べ替えができない図種で**理由つきの淡色ボタン**を出す | ボタンが**無い** (探しても見つからない) |
| **B35** | 構文が崩れた行を指す | 6 種類の誤りすべてで行番号なし |

### B29 — 件数ではなく名前を出す

数百行の図では件数だけでは探せない。3 件以上は先頭 2 件と「ほか N 件」。

```
依存先が無い: 「実装」→ NOSUCH
依存先が無い: 「B」→ X1, 「C」→ X2 ほか1件
```

### B30 — 人が 2 箇所を揃え続けるのは失敗する

単一 HTML でビルド工程が無いので版は直書きするしかない。
**`VERSION` との一致をテストで固定**した。変異 (VERSION だけ上げる) で FAIL を確認。

### B31 — 直すのは線だけでよい

ノードは暗い塗りなので、その上の文字は読める。**薄いのは線だけ**。
背景を暗くする案は設計書に貼ったときと印刷で扱いにくくなるので採らない。
色相は保ち明るさだけ落とす (crit の赤と通常線が書き出しで区別できなくなるのを避ける)。

| 図種 | 直す前 | 直した後 |
|---|---|---|
| flowchart | 1.61 (204,204,204) | **7.11** (88,88,88) |
| sequence / class / er / block / quadrant | 1.61 | **5.41** (106,106,106) |
| timeline | 1.50 (211,211,211) | **5.10** (110,110,110) |

**21 図種中 7 図種が改善、悪化 0。** 残り 4 図種は支配色が線ではなく**塗り**で、
暗くすると上の文字が読めなくなるため触らない。

### B32 — 一律に決めるのが誤りだった

G1 は 35 サイクル「class / er / state の move をどうするか」として 1 つの問いだった。
測ったら**3 つは別の問題**だった。

| 図種 | 要素の `line` が指すもの | 判断 |
|---|---|---|
| class | **宣言行** (`class Dog {`) | 契約経路がブロックごと正しく入れ替える → **実装** |
| er | **関係行** | 文書の形で結果が変わる → 現状維持 |
| state | **遷移行** | **図が壊れる** (隣の状態がコンポジット状態に取り込まれる) → 現状維持 |

### B35 — 捨てていた情報を拾うだけだった

mermaid の例外には `message: "Parse error on line 6"` と `hash.loc.first_line: 5`
が入っているのに、こちらが捨てて「Error」の一語にしていた。
行へ飛ぶ仕組みは既存の `gotoEditorLine` を使う (二重に持たない)。

mermaid が行を返さないときは**推測で指さない**。

## 表示が自分の実装を検査可能にした

**B33 と B35 は、実装中に自分の欠陥をあぶり出した。**

| 機能 | 見つかった欠陥 |
|---|---|
| B33 「線 N 本を濃くしました」 | もともと濃い図で 19 本と出たので内訳を調べたら、`stroke-width: 0px` の**描かれていない線 3 本**を数えていた (19 → 16) |
| B35 「N 行目へ」 | 範囲検査を片方の経路にしか掛けておらず、**2 行の文書で「3 行目へ」**と出た |

どちらも**数や行番号を出したから、その正しさを問えた**。
出さなければ気づけなかった。

## 検証

  特に B31 は「関数を直接呼ぶ試験は通るのに、**呼び出し側を殺しても落ちなかった**」ため、

## 姉妹プロジェクトへの示唆

- **「何本」「何行目」のような数を出すと、その数の正しさを問えるようになる。**
  05 ではそれで 2 件の欠陥が見つかった
- **できない操作は消さずに理由つきで淡色に出す。** 無いものは探しても見つからないので、
  探す時間がそのまま失われる
- **理由を書いたモジュールだけがその形になる**ようにする。
  全パネルを一度に変えると、まだ測っていない図種まで「できない理由」を名乗ることになる
