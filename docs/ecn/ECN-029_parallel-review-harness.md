# ECN-029: 並行レビュー機構と自動合否判定の導入

- **ステータス**: 適用済
- **種別**: プロセス改善
- **バージョン**: (未リリース / master `5d9d2ff`)
- **対象コミット**: `8a52873` 〜 `6115686` のうち検証機構に関わるもの (PR #15)
- **影響ファイル**: tools/review/*.js, tools/review/gate.js, tools/review/lib.js, tools/review/coverage-floor.json, tests/render-oracle.js, tests/gen-rename-cases.js, tests/gen-delete-cases.js, docs/quality-gate.md, docs/review-log.md
- **マイルストーン**: レビュー観点 4 → **22**、ゲート検査項目 **8**

## コンテキスト

このリポジトリには 750 件のユニットテストがあり、すべて通っていた。
それでも実機では図が壊れていた。**テストが通ることは、正しいことの証拠にならない。**

原因は3つあった。

1. テストが「関数の戻り値」しか見ておらず、**mermaid が実際に何を描くか**を見ていない
2. レビューの観点が4つしかなく、観点を足すたびに新しい欠陥が出続けた
3. 「指摘0件」を収束の証拠として扱っていたが、**検査した範囲の外では何も意味しない**

3 が最も重かった。実際 r11 (特殊文字) は更新関数の名前を表で持っており、
表に載っていない図種は静かに検査から外れていた。**21図種中6図種**しか
見ていない状態で「指摘0件」を報告していた。

## 対策

### 実描画オラクル (`tests/render-oracle.js`)

「GUI で操作した結果のテキスト」を実モジュールに作らせ、mermaid に描かせて
before/after を比較する。手書きの期待値を置くと実装が変わったときに嘘になるので、
必ず実モジュールの出力を使う。`expectAbsent` / `expectPresent` で
「消えたはずのものが図に残っていないか」まで見る。

### 並行レビュー機構 (`tools/review/`)

22 の観点を独立プロセスで走らせ、findings を JSON に吐く。

| # | 観点 | # | 観点 |
|---|---|---|---|
| R1 | 破壊しないこと | R12 | 無言の空振り |
| R2 | 削除の巻き添え | R13 | 未知構文の保全 |
| R3 | 実描画 | R14 | 境界値 |
| R4 | UI の一貫性 | R15 | 状態の持ち越し |
| R5 | 利用者の手順 | R16 | 件数の一致 |
| R6 | 並び替え | R17 | Undo/Redo の往復 |
| R7 | 用語と挙動の一貫性 | R18 | キーボード完結 |
| R8 | スケール耐性 | R19 | 網羅の前提条件 |
| R9 | ワークフロー適合 | R20 | 日本語名の非対称 |
| R10 | 保存と開き直し | R21 | 画面に見えているか |
| R11 | 特殊文字 | R22 | 無言の失敗 |

各観点は**変異注入**で有効性を確認してある (実装を壊すと指摘が出ることを実測)。
これをやらないと「0件」が「見ていない」なのか「問題が無い」なのか区別できない。

### 網羅率の計測とゲート化

`tools/review/lib.js` が各レビュアーの検査した図種数を数え、
`out/<name>.coverage.json` に記録する。`coverage-floor.json` を下限として
`gate.js` の `COV` 項目が下回りを FAIL にする。

計測して初めて分かったこと:

| レビュアー | 計測前 | 契約ベース化 / 範囲拡大後 |
|---|---|---|
| r11 特殊文字 | **6/21** | 18/21 |
| r17 Undo/Redo | **2/21** | 19/21 |
| r18 キーボード | **4/21** | 11/21 |
| r6 並び替え | 6/21 | 21/21 |
| r1 破壊検査 | 14/21 | 21/21 |

**関数名の表は検査の網羅を静かに削る。** 表に載っていないモジュールは
黙って対象外になり、モジュールが増えるほど検査は縮む。
契約 (ADR-012 `operations.*`) で呼ぶように書き換えた。

### 自動合否判定 (`tools/review/gate.js`)

終了コードで判定する8項目。

| 項目 | 見るもの |
|---|---|
| G1/G3 | ユニットの件数下限と失敗ゼロ |
| G2 | 実描画オラクルの差分ゼロ (複数スイートを合算) |
| G4/G5 | e2e の件数下限と失敗ゼロ |
| LOOP | 22観点の指摘ゼロ + **出力の鮮度** (ソースより古い結果は未実行扱い) |
| COV | 網羅率が下限以上 |
| G7 | ライセンス表記の整合 |
| BACKLOG | 棚卸しに「残」が無い |
| DOC | **棚卸しと実体の対応** (レビュアーが実在するなら記録がある) |

## 分かったことの一般化

**「指摘0件」は検査した範囲の外では何も意味しない。**
観点を増やす前に、見ている範囲が縮んでいないことを機械で押さえる必要がある。

実際、観点を1つも増やさずに r11 を契約ベースへ書き換えただけで **47件**の
指摘が出た。同様に r1/r2/r6/r9/r14 の契約ベース化で本物の欠陥が3件出ている。

## 姉妹プロジェクトへの横展開
