「組込みソフトウェアアーキテクト、Figma / draw.io / Visio / PlantUML / EA を

## 検出と対策

### スケール耐性

| ID | 内容 | 実測 | 対策 |
|---|---|---|---|
| UI-001 | 500エッジで図が描けない | 300要素 OK / 800要素 (20,483文字) Error | `maxEdges: 100000` を設定。**800要素 OK / 1500要素 OK** |
| UI-005 | 原因を名指しできない場合も「構文エラー」と断定 | 本文に構文誤りは1つも無い | `diagnose.js` にエッジ数・文字数・再帰上限の規則を追加。定型文を「図を描けませんでした」に変更 |

`maxTextSize` は 5,000,000 に上げてあったが `maxEdges` が既定の500のままだった。
3000要素は mermaid の配置計算が再帰上限に当たるので設定では回避できない
(そのことを診断で告げる)。

### 操作コスト / キーボード完結

| ID | 内容 | 対策 |
|---|---|---|
| UI-002 | Delete キーが Gantt でしか効かず、20図種で削除ごとにマウス往復1回 | `operations.delete` 経由の汎用経路に置き換え、実際に消えた数を告げる |
| UI-008 | 追加操作にキーボードから入る手段が無い (候補7キーすべて `body` のまま) | `A` で追加フォームの先頭欄、`E` でエディタへ移動する1打鍵を追加 |
| UI-016 | kanban だけ図をクリックして選べない | 重ね合わせを実装 (列は列名、札は DSL の id で照合) |

`A` → 打鍵 → `Enter` でマウスを1度も使わずに追加できるようになった。

### ワークフロー適合 (Git 管理・成果物の持ち出し)

| ID | 内容 | 実測 | 対策 |
|---|---|---|---|
| UI-007 | 保存ファイルが改行で終わらない | 末尾1行の追加が2行差分になる | 書き出しで常に1つ足し、読み込みで常に1つ落とす (対称) |
| UI-009 | 別セッションで書き出した SVG が同じ id を持つ | どちらも `mermaid-svg-2` | `ma-<ファイル名>` へ付け替え、スタイル59箇所とマーカー12個も追従 |
| UI-010 | PNG が等倍しか出せない | viewBox 788x196 → PNG 788x196 | 「PNGとして保存（2倍）」を追加 (既定は等倍のまま) |
| UI-018 | architecture に日本語が書けない | `["設計"]` なら通る | ラベルに自動で引用符を付ける |

UI-009 の害は2通りある。`url(#id)` は**最初の一致が勝つ**ので2枚目の矢印が
1枚目のマーカーを使い、同じセレクタの CSS は**後が勝つ**ので1枚目が自分の
スタイルを失う。**id 本体だけ直しても意味がない** (マーカーの接頭辞が残る)。

### フィードバック / エラー回復

| ID | 内容 | 対策 |
|---|---|---|
| UI-006 | Gantt 以外では「戻せる」ことが画面に出ない | 全経路で実数を告げる (「N件と関連 M件を削除 — Ctrl+Z で戻せます」) |
| UI-013 | 本文を編集すると追加フォームの書きかけが消える | 再描画の引き金で区別し、本文編集由来のときだけ持ち越す |
| UI-014/015 | クリップボードのコピーが黙って失敗する | 成功 / 権限拒否 / 非対応の3通りを画面に出す |
| UI-020 | mindmap の文字を変えると形状が失われる | `text` と `shape` を取り違えない |

UI-015 が最も重い。押しても何も起きないので、そのまま資料へ貼り付けると
**前にコピーしていた何か**が入る。図が古いのではなく、まったく別のものが
設計書に載る。**失敗が成功と見分けられないのが一番悪い。**

### 発見可能性

| ID | 内容 | 実測 | 対策 |
|---|---|---|---|
| UI-011 | パネルの続きが画面から分からない | 1366x768 で **15/21図種**がはみ出し、スクロールバーの幅は **0px** | 「↓ さらに項目があります」を必要時のみ表示 |

構成そのものの作り替え (折り畳み見出し / タブ分割) は GUI の作り替えなので
MOC の合意が要る。バックログ G2 に残した。

## 結果

- GUI 変更はすべて実機スクリーンショットで確認

## 分かったことの一般化

**測定条件が実利用と違うと、観点を足しても見つからない。**
UI-011 は 1500x950 で測って「8/21・Minor」と判定していたが、
13インチのノートPC (1366x768) では **15/21** だった。
実機レビュアーの画面サイズを 1366x768 に固定した。

**ただし条件を直すだけでは足りない。** 全観点を 1366x768 で走らせ直しても
0件のままだった。「画面に収まっているか」という述語がどこにも無かったからで、
条件の見直しと述語の追加 (R21) は別の作業だった。

**計測が通るのにスクリーンショットで壊れている形がある。**
UI-011 の帯を絶対配置で重ねた案は計測 (15図種で表示) を通過したが、
実機では最後の行に重なって読めなかった。
「GUI の変更を実機スクリーンショット無しで PASS 判定しない」規約がそのまま効いた。
