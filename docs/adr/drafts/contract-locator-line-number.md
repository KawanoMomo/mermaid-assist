# ADR ドラフト: 契約の位置決めは行番号、opts.id は参考値(ADR-012 の改訂案)

- 状態: ドラフト(採番は人間。ADR-012 と ECN-030 の「opts.id を契約の識別子として統一」を改める案)
- 日付: 2026-11-08
- 起点: TICKET-human-20261108-1500-3(backlog E8、作者が測定済み・見送りとしたもの)

## 文脈
ADR-012 の `operations.{update, delete, …}(text, lineNum, …, opts)` は、ECN-030 で「識別子は `opts.id`」と書かれた。
ところが「行番号がずれた本文で契約経路を呼ぶと `opts.id` で正しい要素に届かない」(E8。作者の実測 0/21 図種)。
契約の文言と実装が食い違ったまま残っていた。

## 再実測(2026-11-08、21 図種のひな形。宣言行の直後に `%% shift` を 1 行足し、元の行番号 + `opts.id` で `operations.delete`)
| 結果 | 図種 |
|---|---|
| id で全文を引き、正しい要素が消える | class / er / flowchart / sankey / sequence / state(6) |
| 別の要素を消す・壊す | architecture / c4 / radar / requirement / gitGraph / journey / kanban / timeline / gantt(一部)/ xychart(一部) |
| 何も変わらない | block |
| id が位置からの自動採番で本文に存在しない(`__s_1` 等。id では引けない) | journey / kanban(一部)/ mindmap / packet / pie / quadrant / timeline(一部)/ xychart(8) |
同じ本文の parse から取った行番号なら、本文に ID として書かれた要素は 16 図種すべてで名指しどおりに消える(`tests/contract-locator.test.js`)。

## 決定
**(b) wontfix。契約の位置決めは行番号とし、`opts.id` は参考値とする。**
- `lineNum` は「同じ本文を `parse()` した結果の `element.line`」でなければならない(呼び出し側の責務)。行番号がずれた本文に対する呼び出しは契約外
- `opts.id` は参考値: (1) 1 行に複数の要素がある行(`A[開始] --> B[処理]`、`[*] --> Idle`)で、どれを指すかを決める
  (2) 図種が対応していれば、ID の改名・削除を参照先へ伝播させる。行番号の代わりに要素を探す鍵としては使わない
- 独自キー(`opts.blockId` / `opts.elementName`)を `opts.id` でも受ける後方互換(ECN-030)はそのまま

## 理由
1. 利用者に届く経路が無い: UI は選択を id で持ち、パネルは描画のたびに最新の本文を parse し直して行番号を取る。
   作者の実機確認でも、行を足した直後(描画の間引き 60ms 中)に押して正しい要素が変わった
2. 8 図種の id は位置からの自動採番で本文に存在しない。id 優先に変えるとこれらは逆に壊れる
3. (a) の「21 図種で id 優先」は 15 図種の更新関数を書き換える規模で、ADR-027(更新関数の署名統一)の M2 と同時でないと
   どちらの変更で壊れたか切り分けられない(ADR-027 の判断と同じ)

## 結果
- ECN-030 の「`opts.id` を契約の識別子として統一」は「`opts.id` を参考値の名前として統一(独自キーは後方互換)」と読み替える
- 行番号がずれても id で引けることを保証する図種(上の 6 図種)は、それを壊しても契約違反にはならない(既存の unit が守る範囲はそのまま)
- 将来 (a) に寄せるなら ADR-027 の A 案(全部 `(text, line, field, value, id)`)と同時に行う
