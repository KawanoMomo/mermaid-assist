# ADR-031: パネルの欄名は「ID / ラベル / タイトル」の3語に限る

- **ステータス**: 承認
- **カテゴリ**: UI/UX
- **日付**: 2026-08-22
- **対象プロジェクト**: MermaidAssist
- **関連ADR**: ADR-022 (アクションバーの id 命名規約)

## なぜ起票するか

52箇所を書き換えた規約なのに、根拠が review-log にしか無い。
**散文の規約は守られない**ことが実測で分かっている (E 区分の再検証で
5件中4件が誤りだった) ので、規約と機械検査をセットで記録する。

## 何が起きていたか (実測)

「名前」を指す欄が **9通り**あった。

    ラベル 33 / ID 15 / Name 9 / Title 8 / Text 6 / id 3 /
    `id (任意)` / `name` / `Name (1単語)` / タイトル / 名前 /
    クラス名 / エンティティ名 / グループID / Branch name

図種を跨ぐと同じ欄を毎回読み直すことになる。

## 決めたこと

**意味で分ける。3語だけにする。**

| 語 | 意味 |
|---|---|
| **ID** | 他の行から参照される識別子 (消すと参照が壊れる) |
| **ラベル** | 図に出る文字で、他の行から参照されないもの |
| **タイトル** | 図全体の題 |

但し書き (`(1単語)` / `(任意)`) は付けてよい。

**意味で分けたので機械が判定できる。** `tools/review/terms.js` が
ゲートで毎回検査し、3語の外が現れると FAIL する。変異 (`Name` を1つ戻す) で
検出することを確認済み。

## やらなかったこと

**ドメイン用語は潰さない。** 批判レビューで
「『+ 遷移追加』『+ 関連追加』『+ リレーションシップ追加』を
『+ 接続を追加』に統一する」と提案したが、**その改善案の方が誤りだった**。
「遷移」(UML状態機械) 「関連」(クラス図) はドメイン上正しい用語で、
同じ語に潰すのは一貫性ではなく改悪になる。

実際の摩擦は文言ではなく**位置が図種ごとに動くこと**で、そちらは
パネル構成の作り替え (凍結中) と同じ判断が要る。

## 未解決

- 欄名の日英混在 (日本語23種 / 英語19種) は**凍結**。
  `tag` / `docref` は mermaid のキーワードそのものなので原語が正しく、
  どこまで訳すかは価値判断。`terms.js` が数え続けている
