# ADR-024: 較正の入力健全性 — 横断 ADR-010 の前提の明文化

- **ステータス**: 承認
- **カテゴリ**: アーキテクチャ
- **日付**: 2026-08-19
- **対象プロジェクト**: MermaidAssist (横断 ADR-010 への追記提案)
- **関連ADR**: 横断 ADR-010 (日付⇔ピクセル変換)、横断 ADR-008 (SVGオーバーレイ)

## コンテキスト

横断 ADR-010 は日付⇔ピクセル変換について「描画後の実測から較正する」設計を採り、
`calibrateScale(svgEl, parsedData)` が描画のたびに実 SVG 形状から `pxPerDay` を
再計算する (`src/app.js:116`)。この「毎回再較正するから安全」という性質が、
`useWidth` 変更やズーム変更に対する安全性の根拠として使われてきた。

**しかしこの安全性は「較正の入力が正しい」場合にしか成り立たない。**

Gantt のマイルストーン実装を検討する過程で反例が見つかった。マイルストーンの描画
実体は `rect.task.milestone` の **20×20 + CSS `rotate(45deg)`** であり、
`getBBox()` は**回転前の外接矩形**を返す。つまり較正に渡る x が日付位置ではない。

実測 (設計 04-01〜04-15、ゲート milestone 04-15、実装 04-16〜05-15):

| | pxPerDay | 実装タスクの逆算日付 (正解 2026-04-16) |
|---|---|---|
| マイルストーン無し | 19.267 | 2026-04-16 |
| マイルストーン有り | 18.571 | **2026-04-17** |

**マイルストーンを 1 個置くだけで、無関係なタスクのドラッグ結果がずれる。**
誤差は原点から離れるほど拡大する。

同種の問題は他にもある。`calibrateScale` の候補 rect フィルタは
`width >= 3 && width < chartWidth * 0.95` (`gantt.js:483-486`) で、概観モードの
ような高密度表示では 1 日タスク (0px) や 3 日タスク (2px) が候補から脱落する。
さらに rect とタスクの対応付けは**テキストラベルの y 近傍 (< 30px)** で行うのに、
オーバーレイと選択は**配列インデックス**で行う。行間 24px の高密度表示で実測した
ところ、3 件目のタスクに 4 件目の rect が割り当てられた。

## 検討した選択肢

### A) ADR-010 は現状のまま。個別実装で都度対処する

- メリット: ADR を触らない
- デメリット: 「毎回再較正するから安全」という誤った安心が残り、同じ罠を繰り返す。
  実際、Gantt 仕様の初版はこの安心に依拠して較正への影響を 1 行も書いていなかった

### B) ADR-010 に「入力健全性の前提」を明記し、破る条件を列挙する

- メリット: 較正を使う実装が事前に確認すべき点が明文化される
- デメリット: ADR の改訂が必要

### C) 較正方式そのものを実測ベースから計算ベースへ変更する

- メリット: 描画実体に依存しなくなる
- デメリット: mermaid の内部レイアウトを再実装することになり、ADR-010 が実測方式を
  選んだ理由 (mermaid のバージョン差に追従できる) を捨てることになる

## 決定 (案)

**B) ADR-010 に前提を明記する。**

追記する内容:

1. **較正は「入力が日付位置を表している」ことを前提とする。** 回転・変形された
   shape、または極端に小さい shape が候補に入ると、再較正しても誤った値になる
2. **較正候補の除外規則を実装が明示すること。** 現時点で判明している除外対象:
   - `status === 'milestone'` の rect (回転しているため `getBBox()` が日付位置でない)
3. **rect とモデル要素の対応付けは 1 つの述語で行うこと。** 現在は較正が
   「テキストラベルの y 近傍」、オーバーレイ/選択が「配列インデックス」と別基準で、
   高密度表示で不一致が起きる。**行インデックスに統一する**
4. **較正の健全性は回帰テストで固定すること。** 例:「マイルストーンを 1 個追加しても
   他タスクの逆算日付が変わらない」

## 教訓

1. **「毎回再計算するから安全」は入力の正しさを保証しない。** 再計算はズレの蓄積を
   防ぐが、入力が誤っていれば毎回誤る。
2. **同じ対応付けを 2 つの述語で行うと、境界条件でずれる。** 本件だけでなく、C4 の
   波括弧対応付けや block の group 判定でも同型の欠陥が見つかっている。
3. **描画実体に依存する較正は、描画側の表現手段 (回転・変形) の変化に弱い。** 新しい
   shape を導入するときは較正への影響を必ず確認する。
